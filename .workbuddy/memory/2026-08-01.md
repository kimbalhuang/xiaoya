## 修复 xiaozhi-web 的 vite ws 代理 ECONNRESET/ECONNABORTED 噪声
- 现象：`npm run dev` 下反复出现 `[vite] ws proxy socket error: Error: read ECONNRESET` / `write ECONNABORTED`，伴随服务端 `[ws] 浏览器断开/已连接` 抖动。
- 根因：① `<React.StrictMode>` 使 `App.tsx` 的 `useEffect(connect/close)` 双挂载，产生并发多连接；② `wsClient.scheduleReconnect` 固定 1.5s 死循环重连，每次都冲刷代理 socket；③ vite 代理对重置类错误默认打印。
- 修复：
  - `src/lib/wsClient.ts`：`connect()` 改为幂等（已有 OPEN/CONNECTING 不重复建连）；`onopen` 加过期连接守卫；`scheduleReconnect` 改为指数退避（1.5s→上限15s）+ 0~500ms 随机抖动，连接成功重置计数。
  - `vite.config.ts`：为 `/ws`、`/avatar` 代理加 `configure: silenceProxyReset`，吞掉 ECONNRESET/ECONNABORTED，其它代理错误仍上报。
- 校验：`npx tsc --noEmit` 无本次新增错误（仅 audio.ts/opus.ts 预存）；`npx vite build` 成功（961 模块，EXIT=0）。

## 修复「已显示连接图标却提示『与小智的连接尚未建立』」

- 修复：
  - `server/bridge.js`：① 新增 `connecting` 标志（connect 期间为 true，open/close 置 false）与 `pendingMessages` 缓冲队列；② `handleClientMessage` 在桥接未 OPEN 时：hello→connect；设备缺 token→如实报 DEVICE_NOT_READY；**设备已就绪但仍在连接/重连中→缓冲消息、连上后自动补发，不再误报**；③ `onOpen` 连上后 `flushPending()` 补发缓冲消息；④ `connect()`/`onClose()` 维护 connecting 标志。

## 修复：ECONNABORTED 日志仍刷 + 音乐"没声音"
- 用户反馈：控制台仍刷 `[vite] ws proxy socket error: ECONNABORTED`，且播放歌曲"没有听到声音"。
- 根因1（日志静默失效）：之前 `vite.config.ts` 在 `configure` 里 `proxy.on('error')` 加的监听器会被 vite 在 configure **之后**注册的默认 error 监听器覆盖/并列触发，vite 日志照旧打印。改为**覆盖 `proxy.emit`**：对 `error` 事件中 code 为 ECONNRESET/ECONNABORTED/EPIPE 的直接 `return false` 不派发，vite 的监听器也收不到 → 彻底静默；其余事件/错误码透传。
- 根因2（演示模式无声）：`musicStore.startDemo()` 仅 `setInterval` 模拟进度滚动歌词，**完全不播放音频**，用户点"演示"看到歌词动却没声音属设计如此（之前无说明）。
- 根因3（真实音频可能静音）：`<audio>` 用 `new Audio()` 创建却未挂 DOM，部分浏览器/移动端被自动播放策略拦截。
- 改动：
  - `vite.config.ts`：`silenceProxyReset` 改为覆盖 emit 拦截。
  - `src/store/musicStore.ts`：`getAudio()` 把 audio 元素 `display:none` 后 `appendChild` 到 body（仅一次）；`play()` 处理 `play()` 被拒的 reject（console.warn，不抛错）。
  - `src/components/MusicPlayer.tsx`：演示按钮下加 caption 说明"演示仅预览排版，不出声；要听到声音请先载入音频再播放"。
- 校验：`npx tsc --noEmit` 改动文件零错误；`npx vite build` BUILD_EXIT=0（✓ built 8.13s）。

## 修复：文字先出、语音很久才到（TTS 首句延迟）
- 用户反馈：助手回复文字已显示，但语音（TTS）要等很久才出声。

## 修复「数字人做背景后没有声音」(回归)
- 现象：上一步把 Avatar 改为 `variant="background"` 在 ChatView 全屏渲染后，AI 语音完全没声音（数字人在背景、但听不到回复）。
- 根因（回归）：此前 Avatar 未被渲染，`/avatar` WS 从没连接过，`audioSync` 一直停在默认 `2d` → TTS 帧实时播放、有声。改为背景后 `/avatar` 连上；只要后端下发 `mode:'live'`（FlashHead/数字人场景常见），旧 `audioSync.setMode('live')` 就把所有 TTS 帧**缓冲不播**（它假定 live 视频自带音轨）。而实际画面常为静态 `girl.png` 或 HLS 被静音 → 视频无声音 → 全程静音。即「数字人在、没声音」。
- 修复（解耦 mode 与 TTS 静音）：
  - `src/lib/audioSync.ts`：删除 `mode:'live'|'2d'` 二分逻辑，改为 `videoActive` 单一开关 + `setVideoActive(active)`。`push()` 仅当 `videoActive` 为真才缓冲 TTS，否则实时播放。**默认永远出声**。
  - `src/components/Avatar.tsx`：移除两处 `audioSync.setMode(...)`；改为在 `tryPlay()` 视频**实际带声起播**(`!videoEl.muted`)时 `setVideoActive(true)`，**静音降级/2d/error/video 结束**时 `setVideoActive(false)`（恢复 TTS 并补播缓冲）。`setVideoActive(true)` 转态时清掉 pending，避免视频已发声的语句被重播。
- 效果：无论后端发什么 mode，用户都能听到 AI 语音；只有「真实带声视频正在播放」时才短暂缓冲 TTS（避免双重声音）。演示模式音乐本就静音属正常。
- 校验：`npx tsc --noEmit` 零**本次新增**错误（仅 audio.ts:75 / opus.ts:55 预存）；`npx vite build --outDir .bv-check` BUILD_EXIT=0（964 模块）。
