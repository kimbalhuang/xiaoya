## bridge.js 连接竞态崩溃（晚间三次修复）
- 现象：用户日志后端崩溃 `npm run server exited with code 1`（连带 vite 退出）：`Error: WebSocket is not open: readyState 0 (CONNECTING) at XiaozhiBridge.sendHello (bridge.js:136) at onOpen (bridge.js:120)`。
- 根因：`connect()` 事件回调经实例属性 `this.xzWs` 访问连接而非闭包局部 `ws`；多次触发 connect()（浏览器 hello + scheduleReconnect）时旧 ws 的 open 后触发，this.xzWs 已被新连接(CONNECTING)覆盖 → send 抛错 → 进程崩溃。
- 修复（server/bridge.js 4 处）：①connect 幂等保护（OPEN/CONNECTING 直接 return）；②事件回调全部闭包传 ws（onOpen(ws)/onClose(code,ws)）；③sendHello(ws) 加 `target.readyState===OPEN` 守卫（兼容 handleClientMessage 无参回退 ws||this.xzWs）；④onClose 旧连接忽略（ws!==this.xzWs 时 return，防重连风暴）。
- 验证：node --check 过；9 组竞态 mock 断言过（精确重放崩溃现场：旧 ws open 后触发不崩）；真实 ws echo 4 项过；后端冒烟 get_activation→ready + hello→connect→小智→ready 端到端过；回归 23/0/0。
- 教训：**ws 事件回调必须闭包引用局部连接对象，勿依赖可能被覆盖的实例属性；连接类要有幂等保护 + readyState 守卫**。

## 帧格式勘误：小智下行是裸 Opus 非 [4B 长度]（晚间四次修复，R1 风险成真）
- 现象：用户日志刷屏 `libopus -4 OPUS_INVALID_PACKET`。
- 决定性证据（主理人连真实小智 WS 抓包）：二进制帧 #1 长度 217、hex[0..19]=`db83613c...`，readUInt32LE(0)=1013023707 不是长度；帧头 `db 83` 是 Opus TOC（CELT 模式）→ **真实格式 = 裸 Opus 帧（RFC 6716），无 4B 长度前缀**；文本 JSON 与音频帧按 WS 消息类型区分。指南第 278 行"4 字节小端长度前缀"与实际服务端不符（R1 成真）。
- 修复（3 处统一裸 Opus 直传）：`src/lib/wsClient.ts` handleMessage 整帧 `onBinary?.(buf)`、sendOpus 直接 `ws.send(opusPayload)`（删 getUint32/setUint32）；`server/bridge.js` feedFlashHead 删 readUInt32LE 改 `const opus=buf` 直传 decodeFrame；`opus.ts` 注释同步。
- 验证：端到端抓包 227 帧裸 Opus 直传解码全部成功（samplesDecoded 217920、**0 次 INVALID_PACKET**）；node --check 过；回归 23/0/0。README 与交付报告已同步勘误。
- 教训：**R1 类"协议格式待实测"的风险项不能只按文档实现，必须真实抓包验证；Opus 帧识别看 TOC（db=CELT）**。
