## 排查：数字人连不上服务端、口型表情无变化
- 现象：用户反馈数字人连接不上服务端，口型和表情没有变化。
- 排查结果（三层链路逐一验证）：
  1. `/avatar` WS 通道**本身通**（模拟浏览器连 ws://127.0.0.1:3001/avatar 收到 `{"type":"mode","mode":"2d"}`）。
  2. 但配置是 `FLASHHEAD_MODE=gradio`（.env），应为 `live` → 说明**后端进程（PID 26460）是旧配置启动的，没重启加载新 .env**（index.js 初始 `currentAvatarMode = FLASHHEAD_MODE==='2d' ? '2d' : 'live'`）。
  3. **`127.0.0.1:6006` 今天 ECONNREFUSED**——昨天（8/1 22:54）实测在线（e2e submit 2s 出 m3u8、分片可下载），今天服务不可达。
- 根因：SoulX FlashHead Gradio 服务（AutoDL 云端 `python gradio_app_streaming.py`，本地 6006 经 SSH 转发）**已关闭/转发断开**；后端进程也未重启以加载 gradio 配置。
- 修复动作（用户侧）：
  1. 重启 AutoDL 实例 → SSH 端口转发 `ssh -N -L 6006:127.0.0.1:6006 root@<autoDL地址> -p <端口>`（或改用 AutoDL 公网 Gradio 链接改 FLASHHEAD_URL）。
  2. 重启后端 `npm run server`（或整个 `npm run dev`），使 FLASHHEAD_MODE=gradio 生效。
  3. 验证：连 /avatar 应收到 `mode:"live"`；对数字人说话等 TTS 播完 ~2s 后出现推理视频。
- 备注：本地 6006 可达时链路曾全通（8/1 记录），本次是环境级（云端关机）而非代码问题。代码侧 hls.js 已本地化（8/1），无需再改。
